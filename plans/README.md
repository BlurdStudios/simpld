## Findings from the re-audit that are not yet planned

These were confirmed against the code on 2026-10-17. They are recorded here so they are not lost. Plan them when selected.

- **Default credentials live in the shipped package.** `factory/auth.py:36` (`DEFAULT_USERS`, including `admin/admin123`) and `factory/auth.py:426` (`ensure_default_users`). Production never calls it (`factory/seed.py` is schema-only), but the frozen `.exe` still contains the helper. Move it into `tests/_auth_helper.py` (about 20 test files import `ensure_default_users` from `factory.auth`, so this is a multi-file change; plan it as its own unit). Category: security. Confidence HIGH. Effort M.
- **No code signing.** Neither `build/windows/simpld.iss` nor `.github/workflows/build-windows.yml` signs the `.exe` or installer. Needs a code-signing certificate, which is an external decision. Category: security. Effort M, blocked on certificate.
- **Stale and wine-built artifacts in `dist/`.** `dist/BUILD-INFO.txt` says `wine-11.0`, and `DEMO_WINDOWS.md` says the Wine route is blocked. `dist/Simpld-Setup-1.0.0.exe` should be rebuilt on `windows-latest`, not shipped. Also `data/factory.db` (Oct 13) and `data/print_log.txt` are dev data in the source tree; the spec excludes them from the build, but they should be moved out of the repo or ignored. Category: dx. Effort S.
- **No `LICENSE`.** `.gitignore` and the git repository are done (2026-10-17, commit `85fb000`: `dist/`, `data/`, `.venv/`, caches excluded). A license choice still needs an owner decision. Category: dx. Decision needed (license).
- **Release gates requiring hardware** (not code): Essae scale, Citizen label printer, office A4 printer for multi-page slips, installed-app test on a clean Windows PC, two-PC LAN test. Manual QA; cannot be done by an executor.
- **Stale readiness document.** `PRODUCTION_READINESS.md` still lists defects 1-5 as open and says "NOT READY" from the 2026-10-13 audit. Update it once plan 001 and the defect fixes are verified.
- **Full-suite run is intermittently flaky on this host.** The full suite can segfault (exit 139) at `tests/test_packaging_detect.py:167` (`app.processEvents()`), timing-sensitive: on 2026-10-17 it reproduced in clean HEAD worktrees both with and without the repo `data/` dir while earlier the same day the same code passed the full suite; every test file alone passes. A gdb session on a captured core shows Qt delivering a timer event to a freed/dangling QObject inside `QTimerInfoList::activateTimers` — a host-side Qt/PySide6 issue (system Python 3.14.7 + PySide6 6.11.2; CI uses Python 3.12 + PySide6 6.12.0), not product code (2026-10-17 update: the same hazard family now shows up in Windows CI — see the next bullet). Mitigation in place: plan gates allow one rerun, then a per-file pass table stands as the substitute. Root cause still open; analyses so far rule out plan 007 (identical crash at HEAD) and the repo `data/` dir (crashes with an empty one). Category: tests. Confidence MED. Effort M.
- **Windows CI access violation in the concurrent LAN test (open).** With the whole suite in one interpreter (`windows-latest`, Python 3.12.10, PySide6 6.12.0, `QT_QPA_PLATFORM=offscreen`), `tests/test_lan_transport.py::test_concurrent_roles_stay_isolated` dies with `Windows fatal exception: access violation` (faulthandler dump, 3/3 runs). The fault site moves between a sqlite3 `execute` in `factory/auth.current_user` and the server-side TLS read, so it is process-wide memory state, not that test: the same file passes in a fresh process (CI 10/10; locally 40/40 looped runs), i.e. the LAN server/client code is fine on Windows. Same family as the host full-suite flake above (Qt widget wrappers freed while other threads allocate); prime suspect: parentless Qt widgets and dialogs created by tests and garbage-collected off the GUI thread during the concurrent test's allocation storms. Mitigation in place: CI runs `tests/test_lan_transport.py` in its own step and ignores it in the main suite. Root cause still open; next step is a local reproduction that bisects which earlier Qt test poisons the process. Category: tests. Confidence MED. Effort M.
