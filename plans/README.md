## Findings from the re-audit that are not yet planned

These were confirmed against the code on 2026-10-17. They are recorded here so they are not lost. Plan them when selected.

- **Default credentials live in the shipped package.** `factory/auth.py:36` (`DEFAULT_USERS`, including `admin/admin123`) and `factory/auth.py:426` (`ensure_default_users`). Production never calls it (`factory/seed.py` is schema-only), but the frozen `.exe` still contains the helper. Move it into `tests/_auth_helper.py` (about 20 test files import `ensure_default_users` from `factory.auth`, so this is a multi-file change; plan it as its own unit). Category: security. Confidence HIGH. Effort M.
- **No code signing.** Neither `build/windows/simpld.iss` nor `.github/workflows/build-windows.yml` signs the `.exe` or installer. Needs a code-signing certificate, which is an external decision. Category: security. Effort M, blocked on certificate.
- **Stale and wine-built artifacts in `dist/`.** `dist/BUILD-INFO.txt` says `wine-11.0`, and `DEMO_WINDOWS.md` says the Wine route is blocked. `dist/Simpld-Setup-1.0.0.exe` should be rebuilt on `windows-latest`, not shipped. Also `data/factory.db` (Oct 13) and `data/print_log.txt` are dev data in the source tree; the spec excludes them from the build, but they should be moved out of the repo or ignored. Category: dx. Effort S.
- **No `LICENSE`.** `.gitignore` and the git repository are done (2026-10-17, commit `85fb000`: `dist/`, `data/`, `.venv/`, caches excluded). A license choice still needs an owner decision. Category: dx. Decision needed (license).
- **Release gates requiring hardware** (not code): Essae scale, Citizen label printer, office A4 printer for multi-page slips, installed-app test on a clean Windows PC, two-PC LAN test. Manual QA; cannot be done by an executor.
- **Stale readiness document.** `PRODUCTION_READINESS.md` still lists defects 1-5 as open and says "NOT READY" from the 2026-10-13 audit. Update it once plan 001 and the defect fixes are verified.
- **Full-suite run is intermittently flaky on this host.** Two full-suite runs segfaulted (exit 139) at different points; per-file runs all pass (25 files, exit 0 each), and a rerun of the full suite passes with 185 passed, 1 skipped. The crashing process reports `Extension modules: shiboken6.Shiboken, PySide6.QtCore, ...` and the host runs system Python 3.14.7 with PySide6 6.11.2. This looks like Qt teardown / multi-`QApplication` interaction in one process, not a product bug. It matters because a flaky gate makes plan 002's CI job red at random. Investigate before relying on the gate; candidate fix is one Qt app instance per session plus not destroying it between files. Category: tests. Confidence MED (observed twice, not yet root-caused). Effort M.
